## Trigger Detection

CSD detection requires real browser-side JavaScript activity; cURL alone cannot generate it. The combined script exercises field observation, candidate third-party script loads, and synthetic external requests in one execution.

### Run the Combined Simulation Script

**1. Navigate.** Open `https://client-side-defense.f5-sales-demo.com/#/login`.

**2. Add synthetic markers.** Enter `test@example.com` and `DEMO_PASSWORD` without submitting the form.

**3. Open DevTools.** Select the **Console** tab.

<Screenshot light="/images/devtools-console-light.png" dark="/images/devtools-console-dark.png" alt="Empty DevTools Console ready for script input" />

**4. Run the script.** Paste the script below into the console and press **Enter**.

<Code code={combinedScript} lang="js" title="Combined Detection Script" />

**5. Record evidence.** Confirm the harness attempted field observation, four candidate CDN loads, and two synthetic external requests. Use the Network tab to record which requests occurred. A CDN content error does not prove or disprove CSD detection.

### AI-Automated Execution

AI assistants with browser automation tools (MCP Chrome DevTools, Playwright, Puppeteer) execute the simulation programmatically instead of following the manual steps above:

1. **Navigate with initScript** — first navigate to `about:blank` to ensure a clean document context, then `navigate_page` to `https://$XCSH_DOMAINNAME/#/login` with an `initScript` that saves native browser functions before application instrumentation modifies them, polls for the login fields, fills synthetic markers, and executes the simulation inline.
2. **Dismiss Welcome Banner** — `press_key` with `Escape` if the banner appears.
3. **Wait for completion** — allow the attempted requests to settle; ten seconds is a common lab observation, not a product guarantee.
4. **Capture evidence** — use console messages to confirm the harness completed and Network requests to establish which browser requests were made and their results.

<Aside type="caution">
**zone.js incompatibility** — Juice Shop uses zone.js, which can disrupt browser-automation calls after page load.
Use `navigate_page` with `initScript` to preserve browser functions before application instrumentation runs. Fill fields through the native value setter and run the simulation inside the polling callback.
</Aside>

<Aside type="note">
**initScript accumulation** — each `navigate_page` call with an `initScript` parameter adds the script to a persistent list that runs on every subsequent document load in that browser context. To avoid stale scripts interfering, navigate to `about:blank` between runs or use `new_page` with `isolatedContext` for a clean context.
</Aside>

Operators without browser automation tools use the manual steps above.

<Aside type="tip">
Detection visibility timing varies by tenant, traffic volume, and backend processing. Poll the documented APIs and treat DET-3 as the Phase 3 entry gate rather than relying on a fixed delay.
</Aside>

### What the Script Does

The combined simulation exercises three observable behaviors:

| Behavior | What the Script Does | Evidence to Record |
| --- | --- | --- |
| **Field observation** | Reads existing `input` elements without retaining their values | Console field count plus any later `/formFields` entries |
| **Script injection** | Attempts 4 `&lt;script&gt;` loads from candidate CDN domains | The subset of requests observed in the browser Network log and later domain/script telemetry |
| **Synthetic network signals** | Sends field counts and discard markers via `fetch`; field values never enter the payload | Browser fetch requests plus any matching `/detected_domains` entries |

<Aside type="note">
Observed coverage and API field population vary by run. Do not claim all four CDN candidates were detected unless they appear in this run's evidence.
</Aside>

## Page Tamper HTTP-Header Experiment

### Official mechanism and evidence boundary

F5 documents that Page Tamper takes snapshots of HTTP headers and can raise
`ClientSideDefenseHttpHeaderModified` and `ClientSideDefenseHttpHeaderCompromised` alerts. Collection spans
multiple browser sessions and sequential cycles, and the baseline moves as observations accumulate. See
[About Client-Side Defense](https://docs.cloud.f5.com/docs-v2/client-side-defense/concepts/about-csd) and
[Configure Client-Side Defense](https://docs.cloud.f5.com/docs-v2/client-side-defense/how-tos/configure-csd).

Those official sources do not publish an exact list of monitored headers. The following entries are experiment candidates, not a supported-coverage statement. `Feature-Policy`, when present, is a distinct legacy response header and must not be treated as evidence for `Permissions-Policy`.

Use only these classifications:

- **DETECTED** — a matching Page Tamper alert was retrieved and correlated to the one-header campaign window.
- **NOT DETECTED WITHIN WINDOW** — the mutation and browser telemetry were proven, but no matching alert was retrieved during the bounded search. This does not prove unsupported behavior.
- **AMBIGUOUS** — an alert or traffic signal exists, but timing, scope, or simultaneous changes prevent attribution.
- **INVALID TEST** — the candidate was not mutated, or the mutation/traffic/restoration evidence chain is incomplete.

### 2026-09-24 lab observation

The bounded campaign ran from `2026-09-24T20:22:00.476Z` through `2026-09-24T20:30:11.388Z`. It
produced 108 of 108 fresh browser sessions with HTTP `200`, the exact six simultaneous response-header
mutations above, an injected CSD script, and a CSD `dip` POST. Searches of the documented alert endpoint
across active, inactive, unprocessed, silenced, and inhibited states later returned no
`ClientSideDefenseHttpHeaderModified` or `ClientSideDefenseHttpHeaderCompromised` alert matching the campaign.

Because all six headers changed simultaneously, a generic alert—had one been retrieved—would have been
**AMBIGUOUS** for per-header attribution. No matching alert was retrieved within the searched states and
window, so each tested header is currently **NOT DETECTED WITHIN WINDOW**. This is a bounded tenant observation,
not proof that F5 does not monitor those headers.

Restoration completed at `2026-09-24T21:40:51Z`. The live load balancer had `more_option` set to null,
remained ready with a valid certificate, and returned the canonical state: `Content-Security-Policy`,
`Strict-Transport-Security`, `Referrer-Policy`, and `Permissions-Policy` absent;
`X-Frame-Options: SAMEORIGIN`; and `X-Content-Type-Options: nosniff`. Workstation plus worker raw HTTPS
and browser evidence agreed, Terraform reported no changes, and no worker resources remained.

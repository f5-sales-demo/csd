This page is an inspection walkthrough for the deployed reference architecture. Select either the
[API workflow](/csd/en/demo/) or [Terraform](/csd/en/terraform/) as the resource owner before
deployment.

Choose one ownership mode. Never run the API create/update/delete workflow against resources present in Terraform state.

When Terraform owns the resources, use the console only to inspect status and configuration. Do
not select edit, clone, delete, or save actions.

## Inspect Client-Side Defense

<Steps>
  1. Log in to the **F5 Distributed Cloud Console** 2. Select the **Client-Side
  Defense** workspace 3. Set the namespace to **client-side-defense** 4.
  Navigate to **Manage** &rarr; **Configuration** 5. Inspect the protected-domain
  resource named `client-side-defense` and confirm its protected-domain value is
  `f5-sales-demo.com`; do not modify it
</Steps>

## Inspect the HTTP Load Balancer

The shared architecture uses one HTTP load balancer named `client-side-defense`. It advertises on
the public default VIP, serves HTTPS with an automatic certificate, redirects HTTP to HTTPS, routes
to one origin pool, and inserts CSD JavaScript on all pages. The AWS origin pool uses the deployed
Application Load Balancer hostname as `public_name`; an Azure alternate uses `public_ip`.

<Steps>
  1. Navigate to **Multi-Cloud App Connect** &rarr; **HTTP Load Balancers** 2.
  Open the read-only details for `client-side-defense`; do not choose **Manage
  Configuration** when Terraform owns it 3. Confirm the domain is
  `client-side-defense.f5-sales-demo.com` and the virtual host is ready 4.
  Inspect the **Client-Side Defense** section and confirm JavaScript insertion
  applies to all pages
</Steps>

## Verify Script Injection

<Steps>
1. Open [the reference application](https://client-side-defense.f5-sales-demo.com) in Chrome
2. Press **F12** to open DevTools
3. Go to the **Elements** tab
4. Search for `__imp_apg__` or `zeronaught` in the HTML to locate CSD instrumentation scripts
5. Confirm one or more CSD `<script>` tags are present in the `<head>` — exact paths vary by deployment
6. Confirm the scripts were injected by the load balancer rather than included in the origin application
</Steps>

<Aside type="note" title="UI layout example">
  The following DevTools screenshot is a layout-only orientation aid. Script
  names, paths, and page markup may differ from the current deployment; verify
  injection from the live application.
</Aside>

<Screenshot

The CSD instrumentation scripts are injected by the F5 Distributed Cloud load balancer; they are
not part of the application source.

<Aside type="caution">
  If the scripts are absent, confirm that the protected domain is registered,
  the load balancer uses CSD insertion on all pages, and the browser is reaching
  the application through the F5 Distributed Cloud load balancer rather than
  directly reaching the origin.
</Aside>
